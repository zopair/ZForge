# Rejected and Quarantined Candidates

Purpose: retain evidence for tools that must not be selected, and prevent repeated evaluation waste.

## Record template
- Canonical repository / component:
- Date and target workload:
- State: REJECTED / QUARANTINED
- Exact gate:
- Evidence URL / file / commit:
- Paid or proprietary dependency:
- License finding (including subdirectories/assets/models):
- Security finding:
- Runtime/platform mismatch:
- Maintenance/archival state:
- Test failure and raw result:
- Root-cause confidence:
- Reconsideration condition:
- Alternative candidates:

## Rules
- Rejection is workload-specific where appropriate; do not misrepresent a tool's general status.
- Unknown evidence is QUARANTINED, not REJECTED.
- Never infer legal status from a repository's public visibility.
- Reconsider only when new evidence changes the failed gate.
